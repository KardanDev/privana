# Privana Implementation Plan

> **For agentic workers:** Use domain-scoped subagents and independent review. Steps use checkboxes to track execution.

**Goal:** Deliver a polished, persistent Brazil-first creator marketplace with member, creator, and owner workflows, independent of live payment activation.

**Architecture:** Preserve the existing modular monolith. oRPC domain procedures expose typed operations backed by Prisma; thin Next routes compose domain components. Auth/email and media are separate integrations.

**Tech Stack:** Next.js 16, React 19, Better Auth 1.7.10, Prisma 7, PostgreSQL, oRPC, shadcn/Base UI, Tailwind 4, Bun, Ultracite.

**Spec:** ../specs/2026-10-23-privana-design.md

## Global Constraints

- One named function/component per implementation file within a domain; direct imports, no general-purpose barrel files.
- Portuguese user-facing copy, BRL integer centavos, UTC storage.
- Live payments deferred; no success claims or premium grants from frontend navigation.
- Authenticated, authorized reads and mutations; no premium data in anonymous payloads.
- Preserve user-owned skill/config changes. Work in the existing checkout, as authorized by the user's instruction to proceed using judgment; no git commits or external publication required.

## Review Focus

1. Anonymous requests and expired memberships cannot retrieve subscriber content or media.
2. Cross-user IDs cannot read conversations, edit posts, or enter administration.
3. Suspended creators/users cannot keep publishing or appear in public discovery.
4. Empty databases, missing email/storage credentials, and request errors produce clear states rather than fake success.
5. Mobile navigation, long Portuguese text, loading/empty states, and keyboard forms remain usable.

## Task 1: Persistent product API

Owner: backend agent. Files: packages/db/prisma/schema/*.prisma, packages/api/src/domains/**, packages/api/src/routers/index.ts, packages/api/src/contracts/**.

- [ ] Define shared DTO contracts and indexed relational models for profiles, posts, engagement, memberships, messages, notifications, moderation and audits.
- [ ] Test content access/redaction and authorization boundaries before implementing policies.
- [ ] Implement bounded domain queries/mutations with Zod validation, ownership and participant checks, and server-controlled roles.
- [ ] Generate Prisma client; validate schema; typecheck packages; add opt-in demonstration seed.

## Task 2: Accounts and email

Owner: auth agent. Files: packages/auth/src/**, packages/email/**, apps/web/src/domains/auth/**, apps/web/src/app/(auth)/**, apps/web/.env.schema, apps/web/src/lib/auth-client.ts.

- [ ] Decouple Polar from registration; define optional integration configuration.
- [ ] Implement email verification and reset flows, secure sessions and persisted rate limits, email transport/templates, and a safe owner-bootstrap script.
- [ ] Build accessible Portuguese account forms with actionable errors, pending states, and safe redirects.
- [ ] Test email rendering/transport failures and owner eligibility; typecheck touched packages.

## Task 3: Member experience

Owner: member frontend agent. Files: apps/web/src/domains/discovery/**, creators/**, feed/**, posts/**, messages/**, notifications/**, settings/**, memberships/** and associated app routes.

- [ ] Use shared API contracts for discovery/filtering, creator detail, feed, saved posts and member interactions.
- [ ] Implement persisted messaging, notifications, membership interest and account settings.
- [ ] Provide real loading, empty, error and locked states; no simulated interaction success.
- [ ] Validate TypeScript and keyboard-accessible semantics.

## Task 4: Design system, studio, administration and integration

Owner: root. Files: packages/ui/src/styles/globals.css, apps/web/src/shared/**, apps/web/src/domains/studio/**, admin/**, app layouts and route composition, media domain, docs.

- [ ] Establish royal-purple design tokens, branding, responsive shell, shared formatting and query infrastructure.
- [ ] Compose creator studio forms/metrics and protected admin management using API operations.
- [ ] Implement private media upload/delivery boundary with authorization and explicit configuration states.
- [ ] Integrate deployment variables, migration scripts, README and launch checklist.

## Task 5: Verification and review

- [ ] Run meaningful tests, Prisma validation, typechecks, Ultracite fixes/check and production build.
- [ ] Exercise real workflows in a browser at desktop and mobile sizes; fix observed defects.
- [ ] Obtain independent review, resolve material findings, and record exact verification and remaining setup requirements.
