# Persistent product backend

Implemented the published contract in `docs/api-contract.md`. Domain procedures persist creator profiles, public and subscriber posts, engagement, comments, launch interests, subscriptions, conversations, notifications, preferences, reports, and administration. Prices are integer BRL centavos and responses use ISO timestamps. Lists have server limits of 24 or 50. Empty databases return empty states; requests never fall back to demonstration content.

Every authenticated request re-reads the user from PostgreSQL. Suspended users cannot mutate data, stale admin claims cannot grant administration, and approved active creator profiles control publishing. Public queries require an active creator, active account, and published post. `authorizePostMedia(db, postId, userId?)` and post serialization share `canAccessPost`; anonymous and expired subscribers receive null premium bodies and media URLs. Private object keys never appear in DTOs. Studio validates a registered MediaAsset owned by the current user and the expected MIME type before attaching media. Editing with omitted media preserves the original attachment.

Conversation reads and writes require current participation. Post edits require ownership. Admin status changes and report resolutions record audit events in the same database transaction; the public API has no role mutation or subscription activation operation. Self-suspension and API management of other admins are blocked. Membership interest is persisted and visible after reload, with `INTEREST_REGISTERED` status; it never creates active access or a payment record.

Prisma 7.10.1 validation and client generation succeeded. Initial SQL is in `packages/db/prisma/migrations/20261023160000_initial/migration.sql`; no migration, reset, or seed has run against a database. This initial migration creates the auth tables too. Apply it to a fresh database; an existing starter database needs a reviewed baseline or an incremental diff instead of blindly applying the initial migration.

The opt-in `bun run --cwd packages/db db:seed:demo` command requires `ALLOW_DEMO_SEED=1`, a development `DATABASE_URL`, and a nonproduction environment. It creates four explicitly labeled demo profiles and posts using Unsplash photos, with no sign-in accounts, passwords, engagement, earnings, or subscriptions. It is idempotent and has not been executed.

Verification: backend authorization tests cover anonymous and expired access, suspended accounts and creators, stale session roles, conversation participants, cross-owner editing, unconfirmed or foreign media attachments, premium serialization, content limits, and persisted launch interests. DB/API TypeScript and scoped Ultracite checks pass. Procedure tests use narrow in-memory database doubles to exercise real oRPC middleware, validation, policy, and serialization; a live PostgreSQL workflow test remains part of deployment verification after credentials and migration review. Private blob upload/finalization and delivery are supplied by the web integration.
